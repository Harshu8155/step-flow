# StepFlow Auth Backend

Spring Boot 3 authentication service: **register / login / logout / refresh**, using
Spring Security + JWT (access + refresh tokens) + BCrypt + JPA/Hibernate + **MySQL**.

## How auth works here

- **Access token** — a short-lived (15 min) stateless JWT. Sent on every request as
  `Authorization: Bearer <accessToken>`.
- **Refresh token** — a long-lived (7 day) random token stored in the DB. Used to get a
  new access token when it expires. Because it's in the DB, it can be **revoked** — that's
  what makes real logout possible with otherwise-stateless JWTs.
- **Logout** = revoke the refresh token. The old access token still works until it expires
  (≤15 min); the client just deletes it.

## Prerequisites

- Java 17+
- Maven 3.9+
- A running MySQL server (8.x)

## Configure

Edit `src/main/resources/application.properties`:

- `spring.datasource.username` / `spring.datasource.password` — your MySQL credentials.
- `app.jwt.secret` — **replace** with your own long random string (≥ 32 characters).

## Step 1 — create the database (pre-made schema)

The tables are defined explicitly in [`src/main/resources/schema.sql`](src/main/resources/schema.sql)
(not auto-generated by Hibernate — `ddl-auto=none`). Create them once:

```bash
mysql -u root -p < D:\backend\src\main\resources\schema.sql
```

This creates the `stepflow_auth` database with the `users` and `refresh_tokens` tables.
(Prefer a GUI? Open `schema.sql` in **MySQL Workbench** and run it.)

## Step 2 — run the app

```bash
cd D:\backend
mvn spring-boot:run
```

Server starts on `http://localhost:8080`.

> No Maven on PATH? Open the `D:\backend` folder in **IntelliJ IDEA** or **VS Code**
> (Java + Spring extensions) and run `AuthBackendApplication` — the IDE supplies Maven.

## API docs (Swagger UI)

Once the app is running:

- **Swagger UI:** http://localhost:8080/swagger-ui.html
- **OpenAPI JSON:** http://localhost:8080/v3/api-docs

To test the protected endpoints (`/me`, `/logout`) from Swagger:
1. Call `POST /api/auth/login` (or `/register`) and copy the `accessToken` from the response.
2. Click the green **Authorize** button (top-right), paste just the token (no `Bearer ` prefix), Authorize.
3. Now `GET /api/auth/me` and `POST /api/auth/logout` will send the token.

## Endpoints

| Method | Path                 | Auth        | Body                                  |
|--------|----------------------|-------------|---------------------------------------|
| POST   | `/api/auth/register` | public      | `{ name, email, password }`           |
| POST   | `/api/auth/login`    | public      | `{ email, password }`                 |
| POST   | `/api/auth/refresh`  | public\*    | `{ refreshToken }`                    |
| POST   | `/api/auth/logout`   | Bearer      | `{ refreshToken }`                    |
| GET    | `/api/auth/me`       | Bearer      | –                                     |

\* protected by the refresh token itself being valid & not revoked.

`register` / `login` / `refresh` return:

```json
{
  "accessToken": "eyJhbGci...",
  "refreshToken": "8f3c...uuid",
  "tokenType": "Bearer",
  "expiresInMs": 900000,
  "user": { "id": 1, "name": "Arjun", "email": "a@b.com", "role": "USER" }
}
```

## Quick test (curl)

```bash
# Register
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name":"Arjun","email":"arjun@example.com","password":"password123"}'

# Login
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"arjun@example.com","password":"password123"}'

# Me (use the accessToken from above)
curl http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer <accessToken>"

# Logout (use the refreshToken)
curl -X POST http://localhost:8080/api/auth/logout \
  -H "Authorization: Bearer <accessToken>" \
  -H "Content-Type: application/json" \
  -d '{"refreshToken":"<refreshToken>"}'
```

## Calling it from the React Native app

```js
const API = 'http://10.0.2.2:8080'; // Android emulator -> host machine's localhost

async function login(email, password) {
  const res = await fetch(`${API}/api/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password }),
  });
  if (!res.ok) throw new Error('Login failed');
  const data = await res.json();
  // store data.accessToken + data.refreshToken (AsyncStorage / SecureStore)
  return data;
}
```

> On the Android emulator, `localhost` refers to the emulator itself — use `10.0.2.2`
> to reach your machine. On a physical device, use your PC's LAN IP.

## Notes for production

- Replace `ddl-auto=update` with a real migration tool (Flyway/Liquibase).
- Lock down CORS (`SecurityConfig`) to your real origins.
- Serve over HTTPS and keep `app.jwt.secret` in an env var / secret manager.
- Consider a scheduled cleanup of expired/revoked refresh tokens.
